First of all, you need to have localy exact directory tree as in the
repository, with following modules (assume $KDEREPO contains the top path of
local KDE checkout):

  $KDEREPO/
      trunk/
          l10n-kde4/
              scripts/
              templates/
              gl/
	  l10n-support/
	      templates/
	      scripts/
	      pology/
	      gl/
      branches/
          stable/
              l10n-kde4/
                  scripts/
                  templates/
                  gl/

To maintain this structure locally is a good idea anyway, regardless of
particular uses.

Then you make Pology's scripts available from any location:

  $ export PATH=$KDEREPO/trunk/l10n-support/pology/scripts:$PATH

which is another generally good idea :)

Having the above ready, to initialize the summit for GUI POs, you do:

  $ cd $KDEREPO/trunk/l10n-support
  $ posummit.py scripts/messages.summit gl gather --create --force

After some time (in thruth, a lot :), this will create the summit in
gl/internal/messages, which you can then commit.

This ends the setup.

_From then on you translate exclusively the POs in
$KDEREPO/trunk/l10n-support/gl/internal/messages. Scripty will merge them as
all other POs, so they will get periodically updated as usual.

To fill up the branch POs (stable/trunk) with new translations made in the
summit, from time to time you execute:

  $ cd $KDEREPO/trunk/l10n-support
  $ posummit.py scripts/messages.summit gl scatter

or, if you want to scatter just a particular PO, e.g. Dolphin's:

  $ posummit.py scripts/messages.summit gl scatter dolphin

(note no path and no .po ending -- just the base catalog name).

This is about all that is required for maintenance.

There are however extra niceties possible. Scatter stage is a good choke
point to apply some checks to translation, for examples you could peek into
ja/internal/messages.extras.summit (comments are hopefully descriptive
enough to indicate what's going on :) Then, one can wrestle away merging of
POs from Scripty, and do it locally instead (using one command, of
course) -- this both offloads the central server, and makes summit and
branch POs always in perfect sync.

> I tried this, and noticed that it only creates summit files for 'messages/
> ', not 'docmessages'. Is there a way to work with summit files for
> docmessages too?

Yes, just replace scripts/messages.summit with scripts/docmessages.summit,
and everything will work out symetrically.

A note: the arguments of posummit.py are ordered so that one could do e.g.:

  $ alias summit-kde-nb="posummit.py scripts/messages.summit nb"
  $ alias docsummit-kde-nb="posummit.py scripts/docmessages.summit nb"
  $ ...
  $ summit-kde-nb scatter dolphin
